# BTC 받기

**온라인 지갑에서 받는 주소를 표시하고, ShieldSigner에서 그 주소가 내 지갑의 주소인지 확인**해요.<br> 확인한 주소를 보내는 사람에게 전달한 뒤 입금 상태는 온라인 지갑에서 조회해요. 받는 데 거래 서명은 필요하지 않아요.

## 시작하기 전에

- [준비사항](./#preparation)을 확인하고 실물 ShieldSigner와 호환되는 온라인 워치온리 지갑을 준비해요.
- 시드는 기기에만 불러와요. SeedKeeper를 사용한다면 [시드 불러오기](../seedkeeper/load)를 먼저 진행해요.
- 패스프레이즈를 쓰는 지갑이면 정확히 같은 값을 적용해요. 다른 패스프레이즈는 다른 지갑을 만들어요.
- 이미 연결한 지갑이 있다면 설정을 확인한 뒤 [받는 주소 표시](#receive-address)부터 진행해도 돼요.

## 1. 공개키로 워치온리 지갑을 연결해요 {#connect-wallet}

ShieldSigner에서 **Seeds → 사용할 시드 → Export xpub**을 열어요.<br> 싱글시그 여부, 주소 유형, 계정을 온라인 지갑과 맞추고 해당 앱이 읽을 수 있는 공개키 QR 형식을 선택해요.

온라인 지갑에서는 **워치온리 가져오기 / 하드웨어 지갑 연결**에 해당하는 기능을 열고 기기의 **xpub QR**을 읽어요.<br> 계정의 공개키뿐 아니라 지문과 파생 경로가 올바르게 전달됐는지 확인해요. 시드 단어를 입력해 새 소프트웨어 지갑을 만드는 과정이 아니에요.

| 맞출 항목 | 확인할 내용 |
| --- | --- |
| 네트워크 | 양쪽 모두 Bitcoin Mainnet인지 확인해요. |
| 시드와 패스프레이즈 | 의도한 지갑의 지문인지 확인해요. 지문만으로 주소 검증을 대신하지는 않아요. |
| 지갑 유형 | 이 안내에서는 Single Sig를 사용해요. |
| 주소 유형 | 기존 지갑과 같은 유형을 선택해요. Native Segwit은 한 가지 예시이지 모든 지갑의 필수값은 아니에요. |
| 계정·파생 경로 | 같은 계정의 공개키를 사용해요. 기존 지갑의 값을 임의로 바꾸지 않아요. |

메뉴가 보이지 않거나 가져오기에 실패하면 앱의 하드웨어 지갑·QR 지원 안내를 확인해요.<br> 연결 문제를 해결하려고 **SeedQR이나 개인키를 온라인 앱으로 보내면 안 돼요.**

## 2. 이번에 받을 주소를 표시해요 {#receive-address}

온라인 지갑에서 **Receive / 받기**를 열어요.<br> 화면의 **주소 전체와 주소 QR**을 표시해 두고, 앱에서 확인할 수 있다면 수신 주소의 순서(index)도 확인해요.

이후에는 **이번 입금에 실제로 사용할 주소**를 검증해요.<br> 처음 연결할 때 첫 주소를 확인했더라도, 새로 생성된 다른 주소까지 확인한 것은 아니에요.

## 3. ShieldSigner로 주소를 검증해요 {#verify-address}

1. 기기 홈의 **Scan**을 열고 온라인 지갑에 표시된 **받는 주소 QR**을 카메라로 읽어요.
2. 시드 선택을 요청하면 이 온라인 지갑에 연결한 시드를 선택해요. 패스프레이즈도 맞아야 해요.
3. 지갑 유형이나 파생 정보를 묻는다면 온라인 지갑과 같은 설정으로 진행해요.
4. 주소 검증이 완료됐는지 확인하고, 검증 대상 **주소 전체**가 온라인 지갑에 표시된 값과 일치하는지 대조해요.

기기는 내 시드에서 주소를 계산해 일치 여부를 확인해요.<br> 단순히 QR을 읽었다는 메시지와 **주소 검증 성공**을 구분해 주세요. 검증이 완료되지 않았다면 입금 주소로 사용하지 않아요.

### Address explorer로 직접 대조하는 방법

시드 메뉴의 **Address explorer**에서 같은 주소 유형·계정 설정을 선택하고 **수신 주소 목록**을 열어요.<br> 온라인 지갑의 수신 주소와 같은 순서의 주소를 찾아 전체 문자열을 대조해요. 잔돈 주소 목록과 혼동하지 마세요.

첫 주소가 아닌데 첫 번째 항목만 비교하거나, 주소 앞뒤 몇 글자만 비교해서는 안 돼요.<br> 해당 주소를 찾지 못하면 검색을 억지로 통과시키지 말고 시드·패스프레이즈·계정·주소 유형부터 다시 확인해요.

<Callout type="warning" title="주소가 다르면 입금을 중단해요">
주소 검증은 그 주소가 내 지갑에서 나온 주소인지 확인하는 과정이에요. 복사·붙여넣기 후에도 전달할 주소 전체가 바뀌지 않았는지 다시 확인해요.<br> 가이드나 다른 사람의 화면에 나온 예시 주소를 내 입금 주소로 사용하지 마세요.
</Callout>

## 4. 확인한 주소를 전달해요 {#share-address}

검증한 주소 또는 그 주소 QR만 보내는 사람에게 전달해요.<br> 거래소에서 출금한다면 받는 주소와 함께 **비트코인 메인넷**을 선택했는지 확인해요. 다른 체인의 BTC 토큰이나 별도 결제망을 선택하지 않아요.

처음 연결한 지갑으로 큰 금액을 옮길 때는 소액으로 입금 주소와 확인 절차를 점검한 후 진행해요.<br> 주소를 검증한 뒤에는 입금을 기다리기 위해 ShieldSigner를 계속 켜 둘 필요는 없어요.

## 5. 입금과 확정을 확인해요 {#confirmation}

온라인 지갑의 거래 내역에서 **받은 주소, 금액, TXID, 확정 수**를 확인해요.

| 표시 상태 | 의미 |
| --- | --- |
| Pending / Unconfirmed / 미확정 | 거래를 조회할 수 있지만 아직 블록에 포함되지 않았어요. |
| Confirmed / 확정 | 거래가 블록에 포함됐어요. 이후 블록이 쌓이면서 확정 수가 늘어나요. |

TXID는 어떤 거래인지 구분하는 식별자예요.<br> 전송자의 완료 화면만 믿지 말고 내 지갑에서 실제 입금과 확정 상태를 확인해요. 필요한 확정 수는 거래 상대방이나 서비스의 요구에 따라 달라요.

### 입금이 보이지 않을 때

- 보내는 사람이 실제로 전송했는지, 전송한 거래의 TXID가 있는지 확인해요.
- 전송한 **주소 전체·네트워크·금액**을 다시 대조해요.
- 온라인 지갑의 서버 연결과 동기화 상태를 확인해요.
- TXID가 있다면 같은 네트워크의 거래 조회 도구에서 상태를 확인해요. 외부 조회 서비스에는 주소·거래 조회 정보가 전달될 수 있어요.
- ShieldSigner에서 잔액을 찾거나, 문제 해결을 위해 시드를 온라인에 입력하지 않아요.
